# OpenAgent runtime sign-in

## When to use

Use this only after the current OpenAgent connection explicitly reports missing or expired authentication, such as `MCP_AUTH_REQUIRED` or `MCP_TOKEN_INVALID`, or the user explicitly requests sign-in. Missing tools, an HTTP status alone, business errors, network failure, or an unknown execution result are not proof that login is needed. Do not test authentication before normal calls.

DeepSeek Harness uses this plugin's dedicated `mcp-remote` OAuth bridge. Credentials stay in the selected `DSH_HOME` under `openagent-auth`; the bridge owns token storage and refresh. Never read, print, copy, or edit that storage, and never use credentials from another client.

Missing tools or failed installation verification do not authorize login recovery. Report the actual failed stage and the preserved public error. Do not read tokens, replace native tools with curl, a custom HTTP/MCP client, or another host's connection, or automatically rerun OAuth to change the verification result.

The bridge checks protocol sessions internally; the model does not need to call account or login tools beforehand. The bridge may rebuild a session only when the request has not been sent, an internal check explicitly reports 404, and no other requests are in flight. If a business request has been sent and its result is unknown, stop without replaying it. After the bridge exits, visible tool names or a new conversation do not prove that the connection has recovered. Follow the normal reload rules below; neither is a reason to rerun login.

## One authorization attempt

1. If the bridge has already opened or is waiting for a browser authorization, keep waiting for that same process. Do not start a second login, reopen the OAuth URL, restart the profile, or repeat the business call. Automatic bridge refresh or consent remains part of that connection's attempt.
2. Only after the previous attempt is confirmed ended and the user authorizes recovery, locate the installed `dsh-openagent` package root using the loaded Skill's trusted resource base, then use its `runtime/login.mjs`. Preserve the current `DSH_HOME` and profile. Run `node <installed-package>/runtime/login.mjs` once with the host's actual local terminal and continuation mechanism; do not copy another host's tool arguments.
3. Immediately before launch say “需要登录 OpenAgent 才能继续。正在打开登录页面…” in Chinese or “Please sign in to OpenAgent to continue. Opening the sign-in page…” in English. The bridge owns opening the page. A printed URL does not prove that the page opened; never compensate with a separate browser navigation.
4. Wait on the same process. The login helper has a bounded timeout and suppresses raw authentication output. `OPENAGENT_LOGIN_CONNECTED` plus successful process completion confirms this connection; it does not prove an account query, tool roster, or business result. Say “已登录 OpenAgent” or “Signed in to OpenAgent” only after that result.
5. A denial, cancellation, failure, or confirmed timeout ends the attempt. Preserve the state and report the failed stage without automatically relaunching, removing authentication files, changing endpoints, or resetting the profile. If the attempt's state is unknown, stop and report that uncertainty. A yielded terminal is not a timeout.

When the connection needs to be reloaded, including after the bridge exits or login completes, reload the target profile only with authorization and no active business calls. While Desktop is running, use its actual native plugin page; if a restart is needed, have the user quit normally and reopen it. For connection recovery, do not run `dsh plugin` against a running Desktop profile, force quit the application, or create background restart scripts. The installation guide's first-time online add through that Desktop application's built-in CLI is a separate installation path, not permission for online updates, removal, or connection recovery. Each bundle load automatically runs this sign-in connection check once without retrying, reusing existing valid authorization without reopening its page. MCP mounts only after that same process reports `OPENAGENT_LOGIN_CONNECTED` and exits successfully. Do not run another shell login concurrently or reopen the application to retry a failed or unknown authorization attempt. After recovery, check the OpenAgent tools actually exposed by the target client; reopening the process does not mean verification passed. Do not call account or business tools solely to verify login. Do not replay a Run with an unknown terminal outcome. A later explicit user request can authorize a new read-only account query. An incomplete Installation Check remains incomplete until its authorized verification obtains successful guide and account results. Preserve an existing pending preparation or attempt and query it read-only. For installation continuation, only an unclaimed, unexpired pending preparation with `connection_status=not_started` or `ready` may use a necessary normal reopen; `connecting` waits for the same attempt, and `failed`, `unconfirmed`, missing, or invalid connection metadata stops continuation. Connection `ready` confirms sign-in and MCP initialization, not business verification. Do not create another check, resend the fixed prompt, or rerun OAuth to bypass its state. Login success alone does not permit the fixed completion message.
